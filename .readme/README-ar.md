### مقدمة

******

يمكن لسكربتات AutoJs6 تحميل ملف JAR عبر `runtime.loadJar()` واستدعاء أصناف Java الموجودة داخله. وبما أن Android لا يستطيع تنفيذ bytecode الخاص بـ JVM مباشرة, يجب أولًا ترجمة هذه الملفات إلى DEX; وبشكل افتراضي يتولى المترجم المدمج في AutoJs6 هذه الخطوة.

يقدم هذا الملحق بديلًا: فهو تطبيق يُثبَّت بشكل منفصل, ويُنفِّذ تلك الترجمة بإصدار أحدث من مترجم D8 من Google داخل عمليته المعزولة الخاصة. يسلّم AutoJs6 ملف JAR إلى الملحق, ويستعيد نتيجة DEX, ثم يتحقق منها ويخزنها مؤقتًا ويحمّلها بنفسه; وإذا حدثت أي مشكلة في الملحق, يعود AutoJs6 تلقائيًا إلى مترجمه المدمج, لذا تستمر السكربتات في العمل عادة.

ثبّت هذا الملحق إذا كنت تريد D8 أحدث من المرفق مع AutoJs6, أو تريد أن تعمل الترجمة في عملية معزولة عن AutoJs6, أو تريد ترقية المترجم بشكل مستقل عن تحديثات AutoJs6.

******

### كيف يعمل

******

مع تفعيل الملحق, يمر استدعاء `runtime.loadJar()` تقريبًا بالخطوات التالية:

```text
1. script     calls runtime.loadJar() or runtime.loadJarWithClasspath()
2. AutoJs6    validates and freezes the input JAR, records its size and SHA-256
3. plugin     re-verifies the input, then compiles it with D8 in a private sandboxed process
4. plugin     returns a DEX ZIP (classes.dex, classes2.dex, ...)
5. AutoJs6    independently re-validates the result, caches it, and loads the classes
*  fallback   if anything fails, AutoJs6 retries once with its built-in compiler
```

الملحق مسؤول فقط عن الخطوتين 3 و 4, أي عن "الترجمة" نفسها; أما تثبيت المدخل والتحقق من النتيجة والتخزين المؤقت والتحميل النهائي للأصناف فتبقى دائمًا داخل AutoJs6. لا يتبادل التطبيقان سوى واصفات الملفات عبر Binder, لذا لا يقرأ الملحق مجلد سكربتاتك أبدًا ولا يعرف المسارات الأصلية للملفات. تُخزَّن نتائج الترجمة مؤقتًا وفق محتوى المدخل ومعاملات الترجمة, لذا فإن إعادة تحميل نفس JAR تصيب الذاكرة المؤقتة دون إعادة ترجمة.

### الميزات

******

- تتم الترجمة بواسطة D8 8.13.22; ويمكن للملحق تحديث مترجمه بشكل مستقل عن AutoJs6.
- تعمل الترجمة في عملية الملحق الخاصة ومساحة عمله الخاصة, لذا لا يؤثر أي انهيار أو فشل على العملية الرئيسية لـ AutoJs6.
- تحقق مزدوج: يفحص الملحق حجم JAR و SHA-256 وبنية ZIP ومحتوى الأصناف قبل الترجمة; ويعيد AutoJs6 التحقق من مخرجات DEX بشكل مستقل بعدها.
- يدعم وضعي الترجمة DEBUG و RELEASE, ومخرجات multi-dex, ومعاملات minApi من 24 إلى 36.
- يدعم جميع الأجهزة العاملة بنظام Android 7.0 (API 24) فما فوق; يستخدم API 26+ الأداة D8Command, بينما ينتقل API 24/25 تلقائيًا إلى مسار توافق D8 CLI.
- يدعم البروتوكول V1.1 مسار classpath مرتبًا وقت الترجمة (`runtime.loadJarWithClasspath()`) لترجمة ملفات JAR التي تشير إلى واجهات API خارجية.
- عند أي فشل يعود AutoJs6 إلى المترجم المدمج مرة واحدة على الأكثر, لذا لا تعلق السكربتات على الملحق أبدًا.

### التثبيت والاستخدام

******

تفعيل الملحق يتم بثلاث خطوات: تثبيت AutoJs6 متوافق, ثم تثبيت ملف APK الخاص بهذا الملحق, ثم اختيار الملحق يدويًا في خيارات المطور في AutoJs6. أمران يجب معرفتهما مسبقًا:

- الملحق غير فعال افتراضيًا. مجرد التثبيت لا يغير شيئًا في AutoJs6; يجب تفعيله يدويًا كما هو موضح أدناه.
- يمكن التراجع في أي وقت. العودة إلى Built-in D8/dx في خيارات المطور تستعيد السلوك الأصلي دون إزالة أي شيء.

#### المتطلبات المسبقة

- AutoJs6 build 5270 أو أعلى (من أجل `runtime.loadJar()`); بينما يتطلب `runtime.loadJarWithClasspath()` إصدار مضيف مقترنًا أحدث (استُخدم build 5274 في التحقق).
- يجب أن يأتي المضيف والملحق من نفس المصدر الموثوق وأن تكون توقيعاتهما متطابقة. مع اختلاف التوقيعات لا يمكن اختيار الملحق; استخدم حزمًا منشورة كزوج أو ابنِ الاثنين بنفسك, ولا تتجاوز المشكلة أبدًا بإزالة المضيف أو مسح بياناته.
- عند البناء بنفسك حافظ على أسماء الحزم الثابتة ومكوّن الخدمة أدناه دون تغيير.
- يُنصح بنسخ سكربتاتك وبياناتك المهمة احتياطيًا قبل الترقية.

المعرّفات ذات الصلة هي:

```text
host package: org.autojs.autojs6
plugin package: io.github.supermonster003.autojs6.plugin.dexcompiler
minimum host build: 5270
exact component: io.github.supermonster003.autojs6.plugin.dexcompiler/io.github.supermonster003.autojs6.plugin.dexcompiler.DexCompilerService
```

#### التثبيت والتفعيل

1. ثبّت أو رقِّ إلى إصدار متوافق من AutoJs6.
2. ثبّت ملف APK الخاص بهذا الملحق.
3. افتح AutoJs6, وانتقل إلى الإعدادات > حول التطبيق والمطور, ثم اضغط مطولًا على أيقونة التطبيق للدخول إلى خيارات المطور.
4. انتقل إلى DEX compiler > Raw JAR compiler provider.
5. اختر مكوّن خدمة هذا الملحق (المكوّن exact component المذكور أعلاه) وأكِّد.

للتأكيد مرة أخرى: تثبيت الملحق وحده لا يفعّله, و AutoJs6 لا يختار أبدًا أي provider مكتشف تلقائيًا; الخطوات من 3 إلى 5 ضرورية.

#### تأكيد التفعيل

عد إلى صفحة خيارات المطور. عندما يعرض الملخص مكوّن خدمة هذا الملحق كخيار محدد, فالتفعيل ناجح: منذ ذلك الحين تُوكل ترجمة `runtime.loadJar()` و `runtime.loadJarWithClasspath()` إلى الملحق أولًا.

إذا لم يظهر الملحق في القائمة, أو ظل الملخص يعرض Built-in D8/dx, فتحقق بالترتيب: أن يكون build AutoJs6 لا يقل عن 5270; وأن تتطابق أسماء حزم المضيف والملحق مع ما ورد أعلاه; وألا يكون النظام قد عطّل تطبيق الملحق; وأن يتطابق التوقيعان.

ملاحظة: يعبّر الملخص عن "من هو المحدد حاليًا", لا عن "من نفّذ ترجمة بعينها فعلًا"; فقد تتجاوز ترجمة منفردة الملحق بسبب إصابة الذاكرة المؤقتة أو التراجع عند الفشل (انظر أدناه).

#### مثال سكربت

ضع ملف JAR يحتوي على ملفات `.class` الخاصة بـ JVM في `lib/example.jar` داخل مجلد السكربتات, ثم استدعِ `runtime.loadJar()` كالمعتاد; لا يضيف الملحق أي كائنات JavaScript عامة جديدة, وتُكتب السكربتات تمامًا كما مع المترجم المدمج. استبدل اسم الصنف والدالة في المثال بواجهة API عامة موجودة فعلًا في ملف JAR الخاص بك.

```javascript
"use strict";

const jar = files.path("./lib/example.jar");
if (!files.isFile(jar)) {
    throw new Error("Missing JAR: " + jar);
}

runtime.loadJar(jar);

// Replace this with a public class that actually exists in example.jar.
const Example = Packages.com.example.autojs6.DexPluginExample;
console.log("DEX compiler example: " + Example.answer());
```

إذا كان JAR يشير أثناء الترجمة إلى أصناف موجودة في بيئة التشغيل لكنها ليست جزءًا من JAR نفسه (مثل بدائل API), فاستخدم نقطة الدخول الصريحة بمسار classpath وقت الترجمة:

```javascript
runtime.loadJarWithClasspath(
    files.path("./lib/program.jar"),
    files.path("./lib/compile-api-stubs.jar"),
);
```

ثلاثة أمور يجب معرفتها عن classpath:

- ملفات JAR في classpath تُستخدم فقط لحل المراجع وقت الترجمة; فهي لا تُضمَّن في المخرجات ولا تُحمَّل تلقائيًا.
- إذا كان البرنامج يستخدم تلك الأصناف فعلًا وقت التشغيل, فيجب أن تكون موجودة مسبقًا في سلسلة parent الخاصة بمحمّل الأصناف النهائي (مثل أصناف نظام Android أو الأصناف المرفقة مع AutoJs6). تحميل JAR تابع أولًا عبر `runtime.loadJar()` لا يحقق ذلك: فهو ينشئ محمّلًا شقيقًا فحسب.
- ترتيب classpath المعلن مهم وهو جزء من هوية الذاكرة المؤقتة; وتتطلب نقطة الدخول هذه ملف classpath واحدًا على الأقل.

من جهة أخرى, ملفات `.aar` وملفات `.dex` المترجمة مسبقًا ونقاط الدخول الديناميكية مثل `defineClass()` تُعالج دائمًا عبر المسار المدمج في AutoJs6 ولا علاقة لها بهذا الملحق. وأخيرًا تذكر أن الترجمة ليست فحصًا أمنيًا: لا تحمّل إلا ملفات JAR التي تثق بها.

#### ماذا يحدث عند فشل الترجمة

حتى مع تفعيل الملحق, يظل AutoJs6 يضع مبدأ "يجب أن يستمر السكربت في العمل" أولًا:

- `runtime.loadJar()`: إذا كان الملحق غير متاح, أو فشلت الترجمة, أو انتهت المهلة, أو لم تجتز المخرجات التحقق, يعيد AutoJs6 ترجمة نفس JAR تلقائيًا بالمترجم المدمج D8/dx, مرة واحدة على الأكثر لكل طلب.
- `runtime.loadJarWithClasspath()`: التراجع كذلك مرة واحدة على الأكثر, ويجب أن يسلّم إلى D8 المحلي نفس program و classpath تمامًا; فلا يُتخلى عن classpath أبدًا ولا يُخفَّض بصمت.
- الإلغاء المتعمد (مثل إيقاف السكربت) ليس فشلًا: فهو لا يستدعي أي تراجع بل ينهي التحميل فحسب.
- عندما يعيد الملحق BUSY (جلسة ترجمة واحدة فقط في نفس الوقت), يطبق AutoJs6 القواعد أعلاه; ما عليك سوى إعادة تشغيل السكربت بعد قليل.

وبالتالي فإن نجاح تشغيل السكربت لا يثبت أن ترجمته مرت عبر الملحق; وعندما تحتاج إلى اليقين, استخدم خطوات التشخيص أدناه.

#### استكشاف الأخطاء والإبلاغ

إذا شككت في عمل الملحق, فارجع أولًا إلى Built-in D8/dx وقارن السلوك. عند الإبلاغ عن مشكلة, أرفق قدر الإمكان المعلومات التالية:

- build/إصدار AutoJs6, وإصدار الملحق, واسم المكوّن الكامل من ملخص خيارات المطور.
- طراز الجهاز, وإصدار Android (API), وبنية المعالج (ABI).
- ملف JAR المسبب للمشكلة (أو حجمه بالبايت وقيمة SHA-256), ونص استثناء السكربت الكامل, وخطوات إعادة الإنتاج.

إذا كنت تجيد استخدام ADB, تجمع الأوامر التالية السجلات ذات الصلة (استبدل `<serial>` بالرقم التسلسلي لجهازك; واحذف المسارات الخاصة والمحتوى الحساس من السجلات قبل المشاركة):

```powershell
adb -s <serial> shell dumpsys package org.autojs.autojs6
adb -s <serial> shell dumpsys package io.github.supermonster003.autojs6.plugin.dexcompiler
adb -s <serial> logcat -d -v threadtime AndroidClassLoader:D AndroidRuntime:E *:S
```

#### التعطيل والتراجع والإزالة

- التعطيل المؤقت: في خيارات المطور ضمن Raw JAR compiler provider اختر Built-in D8/dx وأكِّد, ثم أغلق AutoJs6 تمامًا وأعد تشغيله. يُحتفظ بسجل اختيار المكوّن, لذا يمكنك إعادة التفعيل في أي وقت.
- في الحالات الطارئة: يكفي التعطيل وإعادة تشغيل المضيف كما سبق; لا حاجة لإزالة AutoJs6 أو مسح بياناته أو حذف السكربتات.
- إزالة الملحق: ارجع أولًا إلى Built-in D8/dx, ثم أوقف AutoJs6 وأزل ملف APK الخاص بالملحق. تحذف الإزالة كل بيانات الملحق وملفاته المؤقتة; ويستمر AutoJs6 في العمل بمترجمه المدمج.
- بعد إعادة التثبيت يجب التفعيل يدويًا من جديد; فالاختيار السابق لا يُستعاد تلقائيًا.

### الأسئلة الشائعة

******

**س: ثبّت الملحق ولم يتغير شيء. هل هو معطل?**

ج: لا. الملحق معطّل افتراضيًا ويجب تفعيله يدويًا في خيارات المطور (انظر أعلاه); كما أنه يؤثر فقط على خطوة الترجمة في `runtime.loadJar()` و `runtime.loadJarWithClasspath()` دون أي شيء آخر في سكربتاتك.

**س: كيف أتأكد أن ترجمة معينة نفذها الملحق فعلًا?**

ج: ملخص خيارات المطور يعني فقط أن "الملحق محدد". وبما أن الفشل يتراجع تلقائيًا والنتائج تُخزَّن مؤقتًا, فإن نجاح السكربت لا يعني أن الملحق هو من ترجمه; اجمع السجلات كما هو موضح في "استكشاف الأخطاء والإبلاغ".

**س: هل سيجعل هذا الملحق سكربتاتي أسرع?**

ج: أهدافه هي مترجم أحدث وتحقق أكثر صرامة من المدخلات وعزل العمليات, وليست الأداء. تستغرق الترجمة وقتًا مماثلًا تقريبًا للمترجم المدمج, ويخزّن AutoJs6 النتائج مؤقتًا.

**س: هل يدعم الملحق تقليص/تشويش R8? هل وضع RELEASE هو R8?**

ج: لا ولا. هذا الملحق ينفذ ترجمة D8 فقط; و `RELEASE` يختار فقط وضع release في D8 دون أي shrinking أو obfuscation أو mapping. قدرات R8 تخص ملحق provider منفصلًا ومستقلًا.

**س: لماذا يجب أن تتطابق توقيعات المضيف والملحق?**

ج: إنه تحقق أمني متبادل: يمنع التطبيقات الأخرى من انتحال صفة AutoJs6 أمام الملحق, ويمنع ملحقًا معدلًا من انتحال صفة خدمة الترجمة. عند عدم التطابق انتقل إلى حزم منشورة كزوج بدل الإزالة أو مسح البيانات.

**س: هل يتصل الملحق بالشبكة أو يقرأ ملفاتي?**

ج: لا. لا يملك الملحق أذونات شبكة أو تخزين; ولا يمكنه قراءة سوى المحتوى الذي يسلمه AutoJs6 عبر واصفات الملفات, وتوجد ملفاته المؤقتة بالكامل في مجلده الخاص.

### حدود النطاق

******

تجنبًا لسوء الفهم, الأمور التالية خارج نطاق هذا الملحق صراحة:

- لا shrinking ولا optimization ولا obfuscation من R8, ولا ملفات mapping; يختار `RELEASE` فقط وضع release في D8.
- لا تنزيل للتبعيات ولا حل لها (لا تكامل مع Maven/Gradle), ولا ترجمة عبر الشبكة.
- لا معالجة لملفات `.aar` أو `.dex` المترجمة مسبقًا أو bytecode الديناميكي `defineClass()`; فهي تسلك دائمًا المسار المدمج في AutoJs6.
- مسار classpath في V1.1 للترجمة فقط: لا يحزم تبعيات وقت التشغيل ولا ينشئ محمّلات أصناف مدمجة.
- لا ضمان لمخرجات حتمية على مستوى البايت: قد ينتج عن نفس المدخل DEX مختلف لكنه مكافئ بين إصدارات المترجم.
- لا يحل محل تحقق AutoJs6 من المخرجات: يعيد المضيف دائمًا التحقق من نتيجة DEX بشكل مستقل.
- لا يصبح المترجم الافتراضي تلقائيًا أبدًا: التفعيل قرار صريح من المستخدم دائمًا.

### مرجع تقني

******

الأقسام التالية موجهة للمطورين والمكاملين الذين يحتاجون حدودًا دقيقة; ويمكن لمستخدمي الملحق العاديين تجاوزها غالبًا.

#### الإدخال والإخراج

يستقبل البروتوكول V1.0 ملف raw program JAR واحدًا عبر واصف إدخال; ويستقبل V1.1 ملف program JAR واحدًا مع ملف classpath مرتب واحد على الأقل وقت الترجمة داخل نفس حزمة الإدخال المحدودة. وكلاهما ينتج مخرجات بنفس الشكل:

```text
input: JAR with JVM class files
output: DEX ZIP with contiguous classes*.dex entries
compiler: D8 8.13.22
```

#### معرّفات اكتشاف الملحق

يكتشف المضيف الملحق ويستدعيه عبر المعرّفات التالية:

```text
service action: org.autojs.plugin.DEX_COMPILER
plugin id: dex-compiler
protocol provider id: autojs6-d8
engine: dex-compiler
variant: d8
protocol: V1
required host build: 5270
```

يعلن الملحق D8 8.13.22, ونطاق البروتوكول من V1.0 إلى V1.1, وإدخال JAR, وإخراج DEX ZIP, ووضعي DEBUG و RELEASE, و minApi من 24 إلى 36, و multi-dex; ونموذج runtime library هو boot classpath V1 الخاص بالجهاز.

الإصدار 5270 هو الحد الأدنى لمتطلب المضيف في V1.0; ويتطلب `runtime.loadJarWithClasspath()` إصدار مضيف مقترنًا يدعم V1.1 (استُخدم build 5274 في التحقق التمثيلي). لا يحتوي الملحق على مكتبات native, ويغطي جميع بنى ABI للأجهزة بملف universal APK واحد خالص JVM.

#### نموذج الأمان

لا يطلب الملحق أذونات شبكة أو تخزين. خدمة الترجمة محمية بإذن `org.autojs.permission.PLUGIN`, ويتحقق كل استدعاء من اسم حزمة AutoJs6 و UID المستدعي وتوقيعات الطرفين. تنتقل المدخلات والمخرجات كواصفات ملفات وتُنسخ قبل المعالجة غير المتزامنة; وتوجد الملفات المؤقتة فقط في cache الخاص بالملحق وتُنظف بعد انتهاء الترجمة.

#### حدود الموارد

للدفاع ضد المدخلات الخبيثة أو المشوهة, يفرض الملحق حدودًا صارمة في كل مرحلة; وتُرفض الطلبات المتجاوزة لها فورًا:

- ملف JAR المدخل: 64 MiB مضغوطًا كحد أقصى, و 20000 مدخل, و 256 MiB إجمالي بيانات مفكوكة.
- مسار classpath في V1.1: 32 ملف JAR كحد أقصى, و 64 MiB لكل JAR مضغوط, و 128 MiB إجمالي classpath المضغوط, و 256 MiB لحزمة الإدخال كاملة.
- بيانات الأصناف: 128 MiB إجمالًا و 8 MiB لكل صنف كحد أقصى; ونسب الضغط لكل مدخل وإجمالًا محدودة أيضًا.
- مخرجات DEX ZIP: 16 MiB كحد أقصى مع 64 مدخل DEX مرقمة تسلسليًا كحد أقصى; ويمكن للطلبات إعلان سقوف أدنى.
- التزامن: جلسة ترجمة نشطة واحدة فقط لكل عملية; وتتلقى الطلبات الإضافية خطأ BUSY قابلًا لإعادة المحاولة.
- بيانات التشخيص محدودة بـ 64 KiB, مع سقوف منفصلة لنص الأخطاء وطابور الاستدعاءات الراجعة.

#### تنبيهات

- يمنع الإلغاء أو الإغلاق نشر النتيجة فورًا ويقاطع worker, لكن عمل CPU الداخلي في D8 لا يمكن إيقافه بشكل موثوق وقد يستمر في العملية المعزولة حتى تعود الترجمة الحالية.
- بعد الإلغاء تبقى فتحة الجلسة مشغولة حتى يخرج worker فعليًا ويكتمل التنظيف; وتتلقى الطلبات الجديدة BUSY في هذه الأثناء.
- لا يعلن الملحق مخرجات حتمية; وتتضمن هوية الذاكرة المؤقتة إصدار المترجم وبصمة بيئة التشغيل, لذا لا يعاد استخدام نتائج قديمة عند تغير الإصدار.
- لا يقبل V1.1 سوى classpath وقت الترجمة الذي جمّده المضيف وحزمه; فلا مسارات ملفات من المستدعي ولا إعدادات desugared library مخصصة.
- يختلف boot classpath الخاص ببيئة التشغيل بين الأنظمة; ويجب أن تطابق الطلبات بصمة runtime التي يبلّغ عنها provider.

### خارطة طريق التطوير

******

يتقدم التطوير على مراحل, وقد اكتملت المراحل من R0 إلى R4 بأدلة قابلة للمراجعة. يجري العمل على R5 الآن: أعيدت كتابة أدلة المستخدم والتعليمات داخل التطبيق; واكتملت التشخيصات المحدودة والمنقحة وملخص آخر مسار المحفوظ داخل العملية وحالات فشل/استعادة Android المصرح بها; كما أكمل مختبر مستقل مسار «التثبيت → التمكين → تشغيل السكربت النموذجي» دون عوائق. اكتمل معيار R5.2 وسياسة الترقية الرقمية. اجتاز المرشح ذو التوازي المحدود خلايا P95 PSS المجمعة الست كلها, لكنه لم يترق لأن خلايا زمن added P95 الثلاث المصححة لضربة الذاكرة المخبأة مع عملية باردة تجاوزت 100 مللي ثانية. ما زال قبول V1.1 الأوسع على الأجهزة وترقية الإصدار قيد الانتظار. لتعريفات الإنجاز والأدلة لكل بند, انظر:

- [فتح ROADMAP.md ذي قائمة التحقق](https://github.com/SuperMonster003/AutoJs6-Plugin-DEX-Compiler/blob/master/ROADMAP.md)

### البناء

******

```powershell
.\gradlew.bat :app:assembleDebug
```

بناء الإصدار:

```powershell
.\gradlew.bat :app:assembleRelease
```

تأتي معاملات البناء من `version.properties`. الحد الأدنى الحالي لـ SDK هو 24, و SDK المستهدف 36, والحد الأدنى لـ JDK هو 17 ويوصى بـ JDK 21.

توفر ملفات AAR المحلية في مجلد `libs` بالمستودع واجهة ABI الخاصة بالبروتوكول:

```text
common-plugin-api.aar
protocol-wire-api.aar
dex-compiler-api.aar
```

يُجلب المترجم عبر Maven بوصفه D8 8.13.22. توفر ملفات AAR المحلية حدود البروتوكول المستقرة فقط, وناتج البناء هو universal APK بلا مكتبات native.
