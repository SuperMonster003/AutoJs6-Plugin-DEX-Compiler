### Введение

******

Скрипты AutoJs6 могут загружать JAR через `runtime.loadJar()` и вызывать содержащиеся в нём Java-классы. Поскольку Android не может напрямую исполнять байткод JVM, такие JAR сначала должны быть скомпилированы в DEX; по умолчанию этот шаг выполняет встроенный компилятор AutoJs6.

Этот плагин предлагает альтернативу: это отдельно устанавливаемое приложение, которое выполняет эту компиляцию более новой версией компилятора D8 от Google в собственном изолированном процессе. AutoJs6 передаёт JAR плагину, забирает результат DEX, затем самостоятельно проверяет, кеширует и загружает его; при любой проблеме с плагином AutoJs6 автоматически возвращается к встроенному компилятору, поэтому скрипты обычно продолжают работать.

Плагин стоит установить, если вы хотите более новый D8, чем поставляемый с AutoJs6, хотите выполнять компиляцию в процессе, изолированном от AutoJs6, или хотите обновлять компилятор независимо от обновлений AutoJs6.

******

### Как это работает

******

При включённом плагине вызов `runtime.loadJar()` проходит примерно следующие шаги:

```text
1. script     calls runtime.loadJar() or runtime.loadJarWithClasspath()
2. AutoJs6    validates and freezes the input JAR, records its size and SHA-256
3. plugin     re-verifies the input, then compiles it with D8 in a private sandboxed process
4. plugin     returns a DEX ZIP (classes.dex, classes2.dex, ...)
5. AutoJs6    independently re-validates the result, caches it, and loads the classes
*  fallback   if anything fails, AutoJs6 retries once with its built-in compiler
```

Плагин отвечает только за шаги 3 и 4, то есть за саму компиляцию; фиксация входа, проверка результата, кеширование и финальная загрузка классов всегда остаются внутри AutoJs6. Два приложения обмениваются только файловыми дескрипторами через Binder, поэтому плагин никогда не читает каталог ваших скриптов и не знает исходных путей файлов. Результаты кешируются по содержимому входа и параметрам компиляции, поэтому повторная загрузка того же JAR попадает в кеш без повторной компиляции.

******

### Функции

******

- Компиляцию выполняет D8 8.13.22; плагин может обновлять свой компилятор независимо от AutoJs6.
- Компиляция выполняется в собственном процессе и приватной рабочей области плагина, поэтому сбои и ошибки никогда не затрагивают основной процесс AutoJs6.
- Двойная проверка: перед компиляцией плагин сверяет размер, SHA-256, структуру ZIP и содержимое классов JAR; после компиляции AutoJs6 независимо перепроверяет вывод DEX.
- Поддерживаются режимы компиляции DEBUG и RELEASE, вывод multi-dex и параметры minApi от 24 до 36.
- Поддерживаются все устройства с Android 7.0 (API 24) и выше; API 26+ использует D8Command, а API 24/25 автоматически переключаются на совместимый путь D8 CLI.
- Протокол V1.1 поддерживает упорядоченный classpath времени компиляции (`runtime.loadJarWithClasspath()`) для компиляции JAR, ссылающихся на внешние API.
- При любом сбое AutoJs6 не более одного раза возвращается к встроенному компилятору, поэтому скрипты никогда не застревают на плагине.

### Установка и использование

******

Включение плагина занимает три шага: установить совместимый AutoJs6, установить APK этого плагина, затем вручную выбрать плагин в параметрах разработчика AutoJs6. Два момента, которые стоит знать заранее:

- По умолчанию плагин неактивен. Сама по себе установка ничего не меняет в AutoJs6; его нужно включить вручную, как описано ниже.
- Всё обратимо в любой момент. Переключение обратно на Built-in D8/dx в параметрах разработчика возвращает исходное поведение без удаления чего-либо.

#### Предварительные условия

- AutoJs6 build 5270 или выше (для `runtime.loadJar()`); `runtime.loadJarWithClasspath()` требует более новой парной сборки хоста (для проверки использовалась сборка 5274).
- Хост и плагин должны происходить из одного доверенного источника и иметь идентичные подписи. При несовпадении подписей плагин нельзя выбрать; используйте пакеты, опубликованные парой, или соберите оба сами, и никогда не обходите проблему удалением хоста или очисткой его данных.
- При самостоятельной сборке сохраняйте неизменными фиксированные имена пакетов и компонент сервиса, указанные ниже.
- Перед обновлением сделайте резервную копию скриптов и важных данных.

Соответствующие идентификаторы:

```text
host package: org.autojs.autojs6
plugin package: io.github.supermonster003.autojs6.plugin.dexcompiler
minimum host build: 5270
exact component: io.github.supermonster003.autojs6.plugin.dexcompiler/io.github.supermonster003.autojs6.plugin.dexcompiler.DexCompilerService
```

#### Установка и включение

1. Установите или обновите совместимый AutoJs6.
2. Установите APK этого плагина.
3. Откройте AutoJs6, перейдите в Настройки > О приложении и разработчике и удерживайте значок приложения, чтобы войти в параметры разработчика.
4. Перейдите в DEX compiler > Raw JAR compiler provider.
5. Выберите компонент сервиса этого плагина (exact component, указанный выше) и подтвердите.

Повторим: сама установка плагина его не включает, и AutoJs6 никогда не выбирает обнаруженный provider автоматически; шаги 3–5 обязательны.

#### Проверка активации

Вернитесь на страницу параметров разработчика. Когда в сводке выбранным показан компонент сервиса этого плагина, плагин активен: с этого момента компиляция `runtime.loadJar()` и `runtime.loadJarWithClasspath()` в первую очередь поручается плагину.

Если плагина нет в списке или сводка по-прежнему показывает Built-in D8/dx, проверьте по порядку: сборка AutoJs6 не ниже 5270; имена пакетов хоста и плагина совпадают с указанными выше; приложение плагина не отключено системой; подписи обеих сторон идентичны.

Примечание: сводка показывает, «кто выбран сейчас», а не «кто фактически выполнил конкретную компиляцию»; отдельная компиляция всё ещё может миновать плагин из-за попадания в кеш или отката (см. ниже).

#### Пример скрипта

Поместите JAR с файлами `.class` JVM в `lib/example.jar` в каталоге скриптов и вызывайте `runtime.loadJar()` как обычно; плагин не добавляет никаких новых глобальных объектов JavaScript, и скрипты пишутся точно так же, как со встроенным компилятором. Замените имя класса и метод из примера на публичный API, реально существующий в вашем JAR.

```javascript
"use strict";

const jar = files.path("./lib/example.jar");
if (!files.isFile(jar)) {
    throw new Error("Missing JAR: " + jar);
}

runtime.loadJar(jar);

// Replace this with a public class that actually exists in example.jar.
const Example = Packages.com.example.autojs6.DexPluginExample;
console.log("DEX compiler example: " + Example.answer());
```

Если JAR при компиляции ссылается на классы, существующие в среде выполнения, но отсутствующие в самом JAR (например, API-заглушки), используйте явную точку входа с classpath времени компиляции:

```javascript
runtime.loadJarWithClasspath(
    files.path("./lib/program.jar"),
    files.path("./lib/compile-api-stubs.jar"),
);
```

Три вещи, которые нужно знать о classpath:

- JAR из classpath служат только для разрешения ссылок при компиляции; они не упаковываются в вывод и не загружаются автоматически.
- Если программа действительно использует эти классы во время выполнения, они уже должны существовать в родительской цепочке итогового загрузчика классов (например, системные классы Android или классы, поставляемые с AutoJs6). Предварительная загрузка JAR зависимости через `runtime.loadJar()` этого не даёт: она лишь создаёт «братский» загрузчик.
- Объявленный порядок classpath имеет значение и входит в идентичность кеша; эта точка входа требует хотя бы один JAR classpath.

Отдельно: файлы `.aar`, готовые `.dex` и динамические входы вроде `defineClass()` всегда обрабатываются встроенным путём AutoJs6 и никогда не касаются этого плагина. И наконец, помните: компиляция — не проверка безопасности, загружайте только JAR, которым доверяете.

#### Что происходит при сбое компиляции

Даже с включённым плагином AutoJs6 по-прежнему ставит на первое место принцип «скрипт должен продолжать работать»:

- `runtime.loadJar()`: если плагин недоступен, компиляция не удалась, истекло время ожидания или вывод не прошёл проверку, AutoJs6 автоматически перекомпилирует тот же JAR встроенным D8/dx, не более одного раза на запрос.
- `runtime.loadJarWithClasspath()`: откат также не более одного раза и обязан передать локальному D8 ровно те же program и classpath; classpath никогда не отбрасывается и не понижается втихую.
- Намеренная отмена (например, остановка скрипта) не является сбоем: она не вызывает отката и просто завершает загрузку.
- Когда плагин возвращает BUSY (одновременно допускается лишь одна сессия компиляции), AutoJs6 действует по правилам выше; просто повторите запуск скрипта чуть позже.

Следовательно, успешная работа скрипта не доказывает, что его компиляция прошла через плагин; когда нужна уверенность, используйте шаги диагностики ниже.

#### Диагностика и сообщения об ошибках

Если вы подозреваете, что плагин работает неправильно, сначала переключитесь на Built-in D8/dx и сравните поведение. Сообщая о проблеме, по возможности приложите следующую информацию:

- Сборка/версия AutoJs6, версия плагина и полное имя компонента из сводки параметров разработчика.
- Модель устройства, версия Android (API) и архитектура CPU (ABI).
- JAR, вызывающий проблему (или его размер в байтах и SHA-256), полное исключение скрипта и шаги воспроизведения.

Если вы умеете работать с ADB, следующие команды соберут нужные журналы (замените `<serial>` на серийный номер вашего устройства; перед публикацией удалите из журналов приватные пути и чувствительные данные):

```powershell
adb -s <serial> shell dumpsys package org.autojs.autojs6
adb -s <serial> shell dumpsys package io.github.supermonster003.autojs6.plugin.dexcompiler
adb -s <serial> logcat -d -v threadtime AndroidClassLoader:D AndroidRuntime:E *:S
```

#### Отключение, откат и удаление

- Временное отключение: в параметрах разработчика в Raw JAR compiler provider выберите Built-in D8/dx и подтвердите, затем полностью закройте и перезапустите AutoJs6. Запись о выбранном компоненте сохраняется, так что включить его снова можно в любой момент.
- В экстренной ситуации: достаточно отключить и перезапустить хост, как описано выше; не нужно удалять AutoJs6, очищать его данные или удалять скрипты.
- Удаление плагина: сначала переключитесь на Built-in D8/dx, затем остановите AutoJs6 и удалите APK плагина. Удаление стирает все собственные данные и временные файлы плагина; AutoJs6 продолжает работать со встроенным компилятором.
- После переустановки плагин нужно включать вручную заново; прежний выбор не восстанавливается автоматически.

### Частые вопросы

******

**В: Я установил плагин, и ничего не изменилось. Он сломан?**

О: Нет. Плагин по умолчанию отключён и должен быть включён вручную в параметрах разработчика (см. выше); к тому же он влияет только на этап компиляции `runtime.loadJar()` и `runtime.loadJarWithClasspath()` и ни на что больше.

**В: Как убедиться, что конкретную компиляцию действительно выполнил плагин?**

О: Сводка параметров разработчика означает лишь «плагин выбран». Поскольку сбои автоматически откатываются, а результаты кешируются, успех скрипта не означает, что компилировал плагин; соберите журналы, как описано в разделе «Диагностика и сообщения об ошибках».

**В: Сделает ли этот плагин мои скрипты быстрее?**

О: Его цели — более новый компилятор, более строгая проверка входа и изоляция процессов, а не производительность. Компиляция занимает примерно столько же, сколько со встроенным компилятором, а результаты кешируются AutoJs6.

**В: Поддерживает ли плагин сжатие/обфускацию R8? Режим RELEASE — это R8?**

О: Нет и нет. Этот плагин выполняет только компиляцию D8; `RELEASE` лишь выбирает режим release у D8 и не включает shrinking, обфускацию или mapping. Возможности R8 относятся к отдельному независимому плагину-провайдеру.

**В: Почему подписи хоста и плагина должны совпадать?**

О: Это взаимная проверка безопасности: она не даёт другим приложениям выдавать себя за AutoJs6 перед плагином и не даёт подменённому плагину выдавать себя за сервис компиляции. При несовпадении перейдите на пакеты, опубликованные парой, вместо удаления или очистки данных.

**В: Обращается ли плагин к сети или к моим файлам?**

О: Нет. У плагина нет разрешений на сеть и хранилище; он может читать только содержимое, переданное AutoJs6 через файловые дескрипторы, а его временные файлы целиком находятся в его приватном каталоге.

### Границы возможностей

******

Во избежание недоразумений следующее явно не входит в задачи этого плагина:

- Никакого R8 shrinking, оптимизации или обфускации и никаких файлов mapping; `RELEASE` лишь выбирает режим release компилятора D8.
- Никакой загрузки и разрешения зависимостей (нет интеграции с Maven/Gradle) и никакой компиляции по сети.
- Никакой обработки файлов `.aar`, готовых `.dex` и динамического байткода `defineClass()`; они всегда идут встроенным путём AutoJs6.
- Classpath V1.1 предназначен только для компиляции: он не упаковывает зависимости времени выполнения и не создаёт комбинированные загрузчики классов.
- Никакой гарантии детерминированного побайтового вывода: один и тот же вход может дать разные, но эквивалентные DEX в разных версиях компилятора.
- Не заменяет проверку вывода в AutoJs6: хост всегда независимо перепроверяет результат DEX.
- Никогда не становится компилятором по умолчанию автоматически: включение — всегда явное решение пользователя.

### Технический справочник

******

Следующие разделы адресованы разработчикам и интеграторам, которым нужны точные границы; обычным пользователям плагина их, как правило, можно пропустить.

#### Ввод и вывод

Протокол V1.0 получает один raw program JAR через входной дескриптор; V1.1 получает один program JAR плюс как минимум один упорядоченный JAR classpath времени компиляции внутри того же ограниченного входного пакета. Оба производят вывод одинаковой формы:

```text
input: JAR with JVM class files
output: DEX ZIP with contiguous classes*.dex entries
compiler: D8 8.13.22
```

#### Идентификаторы обнаружения плагина

Хост обнаруживает и вызывает плагин по следующим идентификаторам:

```text
service action: org.autojs.plugin.DEX_COMPILER
plugin id: dex-compiler
protocol provider id: autojs6-d8
engine: dex-compiler
variant: d8
protocol: V1
required host build: 5270
```

Плагин декларирует D8 8.13.22, диапазон протокола V1.0–V1.1, вход JAR, выход DEX ZIP, режимы DEBUG и RELEASE, minApi 24–36 и multi-dex; runtime library model — boot classpath V1 устройства.

Сборка 5270 — минимальное требование хоста для V1.0; `runtime.loadJarWithClasspath()` требует парной сборки хоста с поддержкой V1.1 (для репрезентативной проверки использовалась сборка 5274). Плагин не содержит нативных библиотек и покрывает все ABI устройств одним чистым JVM universal APK.

#### Модель безопасности

Плагин не запрашивает разрешений на сеть и хранилище. Сервис компиляции защищён разрешением `org.autojs.permission.PLUGIN`, и каждый вызов проверяет имя пакета AutoJs6, UID вызывающего и подписи обеих сторон. Ввод и вывод передаются файловыми дескрипторами и копируются до асинхронной обработки; временные файлы находятся только в приватном кеше плагина и удаляются по окончании компиляции.

#### Лимиты ресурсов

Для защиты от вредоносного или некорректного входа плагин применяет жёсткие лимиты на каждом этапе; превышающие их запросы отклоняются сразу:

- Входной JAR: не более 64 MiB в сжатом виде, 20000 записей и 256 MiB распакованных данных суммарно.
- Classpath V1.1: не более 32 JAR, 64 MiB на сжатый JAR, 128 MiB сжатого classpath суммарно и 256 MiB на весь входной пакет.
- Данные классов: не более 128 MiB суммарно и 8 MiB на класс; коэффициенты сжатия по записям и в целом также ограничены.
- Выходной DEX ZIP: не более 16 MiB и не более 64 последовательно пронумерованных записей DEX; запросы могут объявлять более низкие потолки.
- Параллелизм: не более одной активной сессии компиляции на процесс; дополнительные запросы получают повторяемую ошибку BUSY.
- Диагностика ограничена 64 KiB, с отдельными лимитами на текст ошибок и очередь обратных вызовов.

#### Предостережения

- Отмена или закрытие немедленно блокирует публикацию результата и прерывает worker, но внутреннюю работу CPU в D8 надёжно остановить нельзя: она может продолжаться в изолированном процессе до возврата текущей компиляции.
- После отмены слот сессии остаётся занятым, пока worker действительно не завершится и не закончится очистка; новые запросы в это время получают BUSY.
- Плагин не декларирует детерминированный вывод; идентичность кеша включает версию компилятора и отпечаток рантайма, поэтому смена версии никогда не переиспользует устаревшие результаты.
- V1.1 принимает только classpath времени компиляции, замороженный и упакованный хостом; никаких путей файлов вызывающего и никакой пользовательской конфигурации desugared library.
- Boot classpath рантайма различается между системами; запросы должны соответствовать отпечатку рантайма, о котором сообщает provider.

### План развития

******

Разработка идёт поэтапно, и этапы с R0 по R4 завершены с проверяемыми свидетельствами. R5 выполняется сейчас: руководства пользователя и встроенные инструкции переписаны; ограниченная обезличенная диагностика, хранимая только в процессе сводка последнего маршрута и разрешённые сценарии сбоя/восстановления Android завершены; независимый тестировщик также прошёл путь «установка → включение → запуск примера» без препятствий. Бенчмарк R5.2 и числовая политика продвижения завершены. Кандидат с ограниченным параллелизмом прошёл все шесть ячеек совокупного P95 PSS, но не продвинут: во всех трёх исправленных ячейках cache hit при холодном процессе добавленная задержка P95 превышает 100 мс. Расширенная приёмка V1.1 на устройствах и продвижение релиза ещё не завершены. Определения готовности и свидетельства по каждому пункту см. здесь:

### Сборка

******

```powershell
.\gradlew.bat :app:assembleDebug
```

Релизная сборка:

```powershell
.\gradlew.bat :app:assembleRelease
```

Параметры сборки берутся из `version.properties`. Текущий минимальный SDK — 24, целевой SDK — 36, минимальный JDK — 17, рекомендуется JDK 21.

ABI протокола предоставляется локальными AAR в каталоге `libs` репозитория:

```text
common-plugin-api.aar
protocol-wire-api.aar
dex-compiler-api.aar
```

Компилятор подключается через Maven как D8 8.13.22. Локальные AAR предоставляют только стабильную границу протокола, а результат сборки — universal APK без нативных библиотек.
